  - Rejection is enforced: **Broken, high (connector half Verified by probe; the missing server listener Believed).** Nothing on the server listens to `session_request_failed`: game_session_manager.gd:140-152 connects it only `if Netcode.is_client`.   - Two peers declaring one session id: **Broken, medium (Verified by probe).** The second peer gets the SAME player_id (network_connector.gd:582-584) and `_player_id_to_peer_id` moves to it (598). MatchStateSynchronizer skips it ("declared while still connected", match_state_synchronizer.gd:119-130) but NetworkedLevel spawns a second `Player_<id>` node (name collision, auto-renamed node, the same replication-error family as H26) and repoints `players_by_id[id]`. Probe `test_duplicate_session_reuses_player_id_and_moves_peer`: the provider rejects the second claim, the second peer gets the same player id, and `_player_id_to_peer_id` now points at it.

  - Reconnect vs claimed ids: a reconnecting client re-declares its sid, which is "already claimed" (edgegap_server_provider.gd:241-251), so validation fails, and reconnect works only because the failure is ignored. Enforcing validation without a re-claim rule would break reconnect (see F8).

- Testability: (a) GUT unit test, no network: instantiate EdgegapServerProvider, set `_allowed_session_ids`, call `server_validate_player_sessions` with good, unknown, duplicate and missing ids, assert signals and `_claimed_session_ids` (cost: 1 h). (c) Harness: a `match-2-clients` variant with a rogue third client declaring a peer's sid (exec agents only; binds ports; ~half a day).
